# Deployment Plan

Last updated: 2026-11-10. **The demo is live on free tiers** (topology below,
evidence in section 6). For step-by-step instructions, including deploying your
own copy, see [`docs/deployment.md`](../deployment.md). This file keeps the
topology, configuration, smoke-test spec and evidence log. A deployment is only
called live once it's verified and recorded in section 6.

## 1. Live topology (free tier)

| Component | Service | URL | Notes |
| --- | --- | --- | --- |
| Web UI | Render static site (`scrag-web`) | https://scrag-web.onrender.com | CDN; never sleeps |
| Web UI mirror | GitHub Pages (`.github/workflows/pages.yml`) | https://syed-waleed-ahmed.github.io/Self-Correcting-RAG/ | Published from `main` |
| API | Render Free web service (Docker), Frankfurt | https://scrag-api.onrender.com | One instance; sleeps after 15 minutes; about a minute to wake; 220 MB peak memory in CI under a 512 MB limit |
| Sample knowledge | NumPy index baked into the image | | Works without the database (D2) |
| Database | Neon Free Postgres + pgvector, Frankfurt (ADR 0008) | | Sessions, uploads, history, jobs, daily budget; scales to zero when idle |
| LLM | Groq free tier | | Server-side key only |

Both Render services come from the Blueprint in `render.yaml` and deploy from
`main`.

## 2. Running the same image locally

```bash
export GROQ_API_KEY=...            # never commit it
docker compose up --build          # API on http://localhost:8000, sample index baked in
# With a local Postgres for sessions, uploads and history:
SCRAG_DATABASE_URL=postgresql://postgres:scrag@db:5432/scrag docker compose --profile db up --build
python scripts/smoke.py --base-url http://localhost:8000
```

## 3. Environment variables

**API (Render)**:

| Variable | Value / note |
| --- | --- |
| `GROQ_API_KEY` | Secret, set in the dashboard. Never in the repo or the browser |
| `SCRAG_DATABASE_URL` | Secret, set in the dashboard. Neon pooled connection string (or Supabase's transaction pooler on port 6543), `sslmode=require` |
| `SCRAG_API_AUTH_TOKEN` | Generated by Render. Operator-only: `/ingest`, sensitive tool approvals, `/admin/stats` |
| `SCRAG_CORS_ALLOW_ORIGINS` | The web UI origins (Render static site, GitHub Pages); never `*` in production |
| `SCRAG_DEMO_MODE` | `true`: rate limits, daily budget, query caps |
| `SCRAG_FORWARDED_IP_HEADER` / `_HOPS` | `x-forwarded-for` / `1` (Render's proxy) |
| `SCRAG_LOG_JSON` | `true` |
| `SCRAG_GENERATOR_MODEL` and the evaluator and guardrail models | Default `qwen/qwen3.8-27b`. Re-check Groq's model list before deploying |

**Web UI:** `NEXT_PUBLIC_API_BASE_URL` (the API URL) is the only variable, and
it is public by design. GitHub Pages also sets `NEXT_PUBLIC_BASE_PATH`. Never
put keys in `NEXT_PUBLIC_*` variables.

## 4. Manual steps (each needs an account on the service)

1. **Groq:** create a key and check the free-plan limits for the chosen models
   on the console's Limits page. Record them in `FREE_TIER_SERVICE_MATRIX.md`.
2. **Render:**
   - New, then Blueprint, from the repository (`render.yaml`: Free instance
     type, Frankfurt).
   - Enter `GROQ_API_KEY` when asked.
   - Note whether a card was required (risk R5).
3. **Neon** (optional; sessions, uploads, history):
   - Create a Free project in Frankfurt, either in the Neon console or through
     Vercel's Neon integration.
   - Paste the **pooled** connection string into Render as
     `SCRAG_DATABASE_URL`. The API enables `vector` and creates its schema on
     first use.
   - Never add a card or upgrade.
4. **GitHub Pages** (optional mirror):
   - Set Settings, then Pages, then Source to "GitHub Actions".
   - Optionally set the repository variable `SCRAG_API_BASE_URL`.
5. **GitHub:** keep the repository public, so Actions and Pages stay free.

## 5. Smoke tests

`scripts/smoke.py --base-url ...` automates these checks against a running API:

1. `GET /health` returns 200 and `index_size > 0` (bundled index).
2. `POST /query` with a curated sample question returns 200, a non-empty
   answer, at least one `used_chunks` entry, and an `evaluation_status` other
   than `unavailable`.
3. `POST /query` with an empty query returns 422; one with whitespace only
   returns 400 with `error=invalid_query`.
4. Every response carries an `X-Request-ID` header.
5. CORS: a preflight from a web UI origin is allowed, and one from another
   origin is rejected.
6. Rate limit (demo mode): a burst beyond the per-IP limit returns 429 with
   `error=rate_limited`.

## 7. Rollback

- **Render:** redeploy the previous successful deploy from the dashboard. The
  image is immutable per commit.
- **Static site:** redeploy the previous deploy in Render. **GitHub Pages:**
  re-run the Pages workflow for the previous commit.
- **Database migrations** (Phase 4): every migration ships with a downgrade.
  Take a manual backup (`pg_dump` through the pooler) before applying a
  migration to the demo project.

## 8. Things never to do

- Run scheduled keep-alive traffic to avoid sleep or pause policies.
- Put a provider key in frontend code or `NEXT_PUBLIC_*` variables.
- Store authoritative state on Render's filesystem (it is wiped on restart).
- Add a payment method to Upstash, or enable Supabase or Render add-ons.
- Commit a database URL, API key or token anywhere, including tests,
  fixtures, screenshots and issue reports.
