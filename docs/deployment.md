# Deploying the free-tier demo

The demo has three parts, all on free tiers:
- **The web UI** is a Render static site, with a GitHub Pages mirror. Both are
  built from `web/`.
- **The API** runs on **Render Free**. The sample knowledge base and the
  embedding model are built into the image, so it works without a database.
- **An optional Postgres database** (Neon Free) adds sessions, uploads and
  history.

The expected cost is EUR 0; see `docs/planning/COST_ZERO_VERIFICATION.md` for
what could change that. Never add a payment method to any of these services.

| Part | URL | Status |
| --- | --- | --- |
| Web UI | https://scrag-web.onrender.com | **Live** (Render static site from the Blueprint) |
| API | https://scrag-api.onrender.com | **Live** (Render Free, deployed 2026-11-10) |

| Database | Neon Free, Frankfurt (created via the Vercel Neon integration) | **Live** (2026-11-10): sessions, uploads and history enabled |

## Deploy your own copy

Everything below works from a fork, with free accounts only. Before creating
the Blueprint, make three edits in your fork:
1. **`render.yaml`, `SCRAG_CORS_ALLOW_ORIGINS`:** replace the two origins with
   your own web UI origins, e.g. `https://<you>.github.io` and
   `https://<your-web-service>.onrender.com`.
2. **`render.yaml`, `NEXT_PUBLIC_API_BASE_URL`** and the `connect-src` entry
   in the `Content-Security-Policy` header (both under `scrag-web`): set your
   API's URL. Render service names are global, so if `scrag-api` is taken,
   Render adds a suffix, and you must use the URL it shows.
3. **GitHub Pages (optional):** set the repository variable
   `SCRAG_API_BASE_URL` to the same API URL, and set Settings, then Pages, then
   Source to "GitHub Actions".

Then follow sections 1 to 3. Nothing in the code is tied to this repository's
URLs.

## 1. API on Render (one time, about 5 minutes)

1. Open https://dashboard.render.com and choose **Sign in with GitHub**.
2. Choose **New -> Blueprint**, select the `Self-Correcting-RAG` repository,
   and keep the branch `main`. Render reads `render.yaml`: one **Free** web
   service in Frankfurt, built from the `Dockerfile`, with demo mode on and
   CORS already set for the GitHub Pages origin.
3. Render asks for a single value, `GROQ_API_KEY`. Paste your key from
   https://console.groq.com/keys. It stays on the server and is never sent to
   the browser.
4. Click **Apply**. The first build takes a few minutes.
5. If the service URL is not `https://scrag-api.onrender.com` (Render adds a
   suffix when that name is taken), point the web UI at the real one:

   ```bash
   gh variable set SCRAG_API_BASE_URL --body "https://<your-service>.onrender.com"
   gh workflow run pages.yml
   ```

`SCRAG_API_BASE_URL` is a repository variable, not a secret: the API URL is
public. `SCRAG_API_AUTH_TOKEN` is generated by Render. You only need it to call
`/ingest` on the demo, sending it as `X-API-Key`.

## 2. Optional: a database for sessions, uploads and history (Phase 4)

Everything above works without a database. To enable the session endpoints:

1. Create a free account at https://neon.com (Sign up with GitHub works) and a
   **Free** project in **AWS Europe Central 1 (Frankfurt)**, next to the API.
   Don't add a card and don't upgrade: the Free plan never bills overage.
2. In **Connect**, choose the **pooled** connection and copy the string. It
   looks like
   `postgresql://user:password@ep-...-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
3. In the Render dashboard, open `scrag-api`, then **Environment**, and add
   `SCRAG_DATABASE_URL` with that value. The value is secret: never commit it.
   Saving restarts the service.
4. On the first request that needs it, the API connects, enables `vector` and
   applies the migrations. Check that it worked:

   ```bash
   curl -s https://scrag-api.onrender.com/api/v1/health      # "persistence": "unknown" until first use
   curl -s -X POST https://scrag-api.onrender.com/api/v1/sessions
   ```

   The second call returns a session token, and `/health` then reports
   `"persistence": "ok"`.

Supabase also works. Use its **transaction pooler** string (port 6543), because
Supabase's direct connections are IPv6-only and Render's outbound traffic is
IPv4. Note that a Supabase Free project pauses after 7 idle days until it is
restored by hand (ADR 0008).

No keep-alive is needed or wanted. With no visitors, the API sleeps, the
database scales to zero, and both wake on the next request.

## 3. Verify and record evidence

```bash
python scripts/smoke.py --base-url https://scrag-api.onrender.com --live-query
```

Then open the web UI:
- the status pill shows **API online** (or "Waking server" first);
- a sample question returns an answer labelled **Recorded run**;
- **Run live** returns a **Live run**;
- **Retrieval only** returns ranked chunks.

Add a row to the evidence log in `docs/planning/DEPLOYMENT_PLAN.md` (date,
commit, URLs, smoke-test output).

## 4. Optional: Vercel instead of GitHub Pages

Import the repository at https://vercel.com:
- set **Root Directory** to `web`;
- set `NEXT_PUBLIC_API_BASE_URL` to the API URL;
- leave `NEXT_PUBLIC_BASE_PATH` unset.

Then add the Vercel origin to `SCRAG_CORS_ALLOW_ORIGINS` in `render.yaml`, for
example `["https://syed-waleed-ahmed.github.io", "https://<app>.vercel.app"]`.

## What to expect from free tiers

- **Cold starts.** The API sleeps after 15 minutes without traffic, and the
  first request takes about a minute. The UI shows a "waking the server" state.
  Don't add keep-alive pings: they work around the provider's policy.
- **Quotas.** Live AI queries are capped in layers:
  - the global `SCRAG_DEMO_DAILY_QUERY_BUDGET` (default 30 per UTC day);
  - each visitor's share of it, `SCRAG_DEMO_CLIENT_DAILY_RUNS` (default 10;
    an agent run costs 2);
  - the per-client rate limit on expensive endpoints;
  - a coarse per-client flood guard on all requests (health checks exempt).

  Sample questions are answered from recorded runs and use no quota. See the
  [threat model](threat-model.md) for what each layer protects, and
  [load-testing.md](load-testing.md) for measurements.
- **Monitoring.** `.github/workflows/live-check.yml` smoke-tests the live API
  and both web hosts once a day (07:17 UTC), using a recorded sample answer, so
  it spends no live budget. A failed scheduled run makes GitHub email you. Run
  it any time from the Actions tab.
- **Model availability.** Groq changes its free model list. A retired or
  rate-limited model falls back to `SCRAG_LLM_FALLBACK_MODELS` on its own (the
  logs say `falling back to ...`). To replace it for good, pick a current model
  at https://console.groq.com/docs/models and set `SCRAG_GENERATOR_MODEL`,
  `SCRAG_EVALUATOR_MODEL` and `SCRAG_GUARDRAIL_MODEL` on the Render service.
  If queries fail with `llm_error`, both models are gone: do the same.
- **Client IP.** Rate limits and quotas key on the visitor's address. Render
  sits behind Cloudflare, so the address comes from `CF-Connecting-IP`
  (`SCRAG_FORWARDED_IP_HEADER=cf-connecting-ip`). Cloudflare sets it to the
  connecting client and overwrites any value a client sends.
  - `X-Forwarded-For` doesn't work here. It arrives as `client, cloudflare,
    render-internal-proxy`, its first entry is whatever the client sent, and
    its last is one of a few internal proxies that every visitor shares.
  - **How to check it:** after a deploy, send about 30 rapid `/search`
    requests. A correct setup allows the burst of 3.
  - Until 2026-11-11 the demo keyed on the last hop and allowed 6, because two
    internal proxies were taking turns.
  - After the 0.4.0 deploy it allows exactly 3.
  - Render applies a `render.yaml` environment change as a second,
    Blueprint-triggered deploy after the code deploy. Probe after both
    finish.

## Leaving it unattended

The demo is built to run without anyone watching it. This happens on its own:
- **Deploys.** Every merge to `main` redeploys the API and both web hosts.
- **Monitoring.** The daily live check (07:17 UTC) emails you if it fails.
- **Dependency updates.** Dependabot opens grouped update PRs once a month,
  and security fixes as soon as an advisory is published. CI (including the
  container's memory check at 512 MB) and CodeQL run on each one, and the load
  test runs too when the Docker base image changes.
- **Clean-up.** While the API is awake, its worker deletes expired sessions
  with their uploads and history, and per-visitor counters from earlier days.
- **Model changes.** A retired or rate-limited model falls back to the next
  one (see "Model availability" above).

This needs you:

| When | What to do |
| --- | --- |
| A Dependabot PR is green | Merge it. Render redeploys, and the next live check confirms it |
| A Dependabot PR is red | Open the failing check. It's usually a major version with breaking changes: close the PR, and Dependabot stops proposing that version |
| The live check emails a failure | Open the run: the smoke output names the failing check. Retired models: set new ones (above). A Render, Neon or Groq outage: re-run the workflow later from the Actions tab |
| On the 1st of each month | The cost check in `docs/planning/COST_ZERO_VERIFICATION.md`: Render billing (no card, $0), Neon usage, GitHub Actions billing |
| After 60 days without commits | GitHub pauses scheduled workflows (the live check and CodeQL's weekly scan) in public repositories, and emails you first. Merging update PRs counts as activity. To restart one: Actions, then the workflow (**Live check**), then **Enable workflow** |
| A key leaks | Rotate `GROQ_API_KEY` in the Groq console and update it on the Render service. A new `SCRAG_CLIENT_KEY_SECRET` only resets today's per-visitor shares |

## Updating the sample answers

The recorded answers in `data/demo/samples.json` are only served while the
sample corpus is unchanged (the file stores a corpus fingerprint). After
editing `data/docs`, re-record them:

```bash
python scripts/record_samples.py    # needs GROQ_API_KEY; ~8 live pipeline runs
```

Commit the updated file and push; Render redeploys automatically.

## Running the same image locally

```bash
docker build -t scrag .
docker run --rm -p 8000:8000 -e GROQ_API_KEY=... -e SCRAG_DEMO_MODE=true scrag
python scripts/smoke.py --base-url http://localhost:8000 --live-query
```
