# Deploying the free-tier demo

This deploys the API to **Render Free** and the web UI to **Vercel Hobby**.
Neither needs a database. The sample knowledge base and the embedding model are
built into the API image. The expected cost is EUR 0; see
`docs/planning/COST_ZERO_VERIFICATION.md` for what could change that.

The setup takes about 10 minutes and needs three accounts: GitHub (already
used), Render and Vercel. Nothing here requires a payment method, and none
should be added.

## 1. API on Render

1. Sign in at https://dashboard.render.com with GitHub.
2. Choose **New -> Blueprint**, pick the `Self-Correcting-RAG` repository, and
   keep the branch `main`. Render reads `render.yaml`. That file defines one
   **Free** web service in Frankfurt, built from the `Dockerfile`, with demo
   mode enabled.
3. Render prompts for two values:
   - `GROQ_API_KEY`: your Groq key (https://console.groq.com/keys). It stays on
     the server and is never sent to the browser.
   - `SCRAG_CORS_ALLOW_ORIGINS`: enter `["*"]` for now; you'll tighten it in
     step 3.
4. Apply. The first build takes a few minutes: it installs the package,
   downloads the embedding model and builds the sample index.
5. Note the service URL, for example `https://scrag-api.onrender.com`, and run
   the smoke test from your machine:

   ```bash
   python scripts/smoke.py --base-url https://scrag-api.onrender.com --live-query
   ```

`SCRAG_API_AUTH_TOKEN` is generated by Render. You only need it to call
`/ingest` on the demo, sending it as `X-API-Key`.

## 2. Web UI on Vercel

1. Sign in at https://vercel.com with GitHub and choose **Add New -> Project**.
2. Import the repository and set **Root Directory** to `web`. Vercel detects
   Next.js automatically.
3. Add one environment variable:
   `NEXT_PUBLIC_API_BASE_URL = https://scrag-api.onrender.com` (your Render URL).
4. Deploy and note the URL, for example `https://scrag-demo.vercel.app`.

## 3. Lock CORS to the web UI

In Render, go to the service's **Environment** page, set
`SCRAG_CORS_ALLOW_ORIGINS` to `["https://scrag-demo.vercel.app"]` (your exact
Vercel URL), and save. Render redeploys automatically.

## 4. Verify and record evidence

Open the Vercel URL:
- the status pill shows **API online** (or "Waking server" first);
- a sample question returns an answer labelled **Recorded run**;
- **Run live** returns a **Live run**;
- **Retrieval only** returns ranked chunks.

Then add a row to the evidence log in `docs/planning/DEPLOYMENT_PLAN.md` (date,
commit, URLs, smoke-test output).

## What to expect from free tiers

- **Cold starts.** The API sleeps after 15 minutes without traffic, and the
  first request takes about a minute. The UI shows a "waking the server" state.
  Don't add keep-alive pings: they work around the provider's policy.
- **Quotas.** Live AI queries are capped by `SCRAG_DEMO_DAILY_QUERY_BUDGET`
  (default 30 per UTC day) and by the per-client rate limit. Sample questions
  are answered from recorded runs and use no quota.
- **Model availability.** Groq changes its free model list. If queries start
  failing with `llm_error`, check https://console.groq.com/docs/models and set
  `SCRAG_GENERATOR_MODEL`, `SCRAG_EVALUATOR_MODEL` and `SCRAG_GUARDRAIL_MODEL`
  in Render.
- **Client IP.** Rate limiting uses the address Render's proxy appends to
  `X-Forwarded-For` (`SCRAG_FORWARDED_IP_HOPS=1`). If every visitor seems to
  share one limit, the hop count is wrong for Render's current proxy chain:
  check the API logs.

## Updating the sample answers

The recorded answers in `data/demo/samples.json` are only served while the
sample corpus is unchanged (the file stores a corpus fingerprint). After
editing `data/docs`, re-record them:

```bash
python scripts/record_samples.py    # needs GROQ_API_KEY; ~8 live pipeline runs
```

Commit the updated file and push; Render and Vercel redeploy automatically.

## Running the same image locally

```bash
docker build -t scrag .
docker run --rm -p 8000:8000 -e GROQ_API_KEY=... -e SCRAG_DEMO_MODE=true scrag
python scripts/smoke.py --base-url http://localhost:8000 --live-query
```
